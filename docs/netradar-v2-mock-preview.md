# v2 목업 화면 테스트

2026-11-18 사용자가 전달한 팀 요청: 백엔드 API 수정은 백엔드 담당자가 진행하고, 프런트 화면 테스트는 먼저 목업 데이터로 진행한다.
기준은 `netradar-v2-frontend-changes.md` 및 사용자가 제공한 v2 개요·파트별 계획·유저플로우다.

## 실행과 확인

`front/`에서 `npm ci` 후 `.env.example`을 `.env.local`로 복사하고 `npm run dev`를 실행한다.
`VITE_API_MODE=demo`, `VITE_DEMO_VERSION=v2`(기본값)에서 이용 안내에 동의하고 **데모로 둘러보기**를 선택한다.

1. 수요 지도: 수요 지수/인구, 지금/+30/+60분, 장소 검색·지도 이동·목록·상세를 확인한다. 온라인 타일이 실패해도 목록·상세는 이용할 수 있다.
2. 급증 알림: 앞으로 60분 내 피크가 있는 도달 가능한 예시 중 최대 3곳을 표시한다. 추천 출발 시각, 데이터 생성 시각에 출발할 때의 도착 시각·지수, 피크 구간을 구분한다. 이동 시간은 직선거리 기반 목업이며 실제 교통 정보가 아니다.
3. 이벤트: 한국 시간 기준 오늘 남은 일정, 공항/공연/열차/막차 필터, 장소 상세 이동을 확인한다.
4. 동선: 상세의 동선 추천/바로 출발, 출발지 선택, 선택적 목적지, 최대 3곳 경유지와 도착 시점 지수를 확인한다.
5. 모의 운행: 도착→대기/연장→탑승 또는 다음 장소→하차→재추천/종료를 진행한다. 대기 중 새로고침과 중복 버튼 입력 뒤 기록이 중복되지 않는지 확인한다.
6. 리플레이: 저장한 모의 운행 목록과 **예시 리플레이 보기**를 구분한다. 예보 인구·관측 인구(예시)는 모두 명 단위이며 관측 누락은 0이 아닌 빈 구간으로 표시한다.
7. 마이페이지: 프로필·즐겨찾기·로그아웃을 유지하고, 지도 급증 알림 표시 설정을 별도로 저장한다. 푸시 알림 전송은 없다.

## 데이터와 API 경계

`src/v2/types/demand.ts`와 `src/v2/types/drive.ts`는 **프런트 내부 목업 모델 초안**이다. 실제 백엔드/OpenAPI 명세로 확정한 것이 아니다.
v2 화면은 현재 별도의 API 요청을 하지 않으며 `src/v2/services/demand.ts`의 명시적인 목업 스냅샷을 사용한다. 실제 모드에서 이 목업 서비스가 호출되면 오류를 반환한다.
`VITE_API_MODE=live`에서는 기존 v1 화면·서비스를 유지하여 준비되지 않은 v2 계약으로 운영 서버를 호출하지 않는다. 기존 live 실패를 목업 성공으로 바꾸지 않는다.

| 항목      | 목업에서의 선택                                        | 실제 연동 때 확인할 것                       |
| --------- | ------------------------------------------------------ | -------------------------------------------- |
| 장소      | 대표 6곳, 근사 폴리곤                                  | 실제 장소 마스터·공식 경계·대상 범위         |
| 좌표      | 닫힌 외곽 링, `[경도, 위도]`                           | GeoJSON/MultiPolygon 여부, 좌표 규약         |
| 시점      | 0/30/60분, `generatedAt` ISO 타임존 포함               | `offset`/`horizon`, 표기와 생성 시각 의미    |
| 표시 구간 | 각 시점 `range`, `populationRange`가 low/moderate/high | 서버 `range` 의미·색상 규칙·급증 판정 기준   |
| 수요 지수 | 0~100 정수                                             | 실제 예측 산출·보정·검증                     |
| 이벤트    | 공항/공연/열차/막차, 오늘 남은 예시                    | 지연·취소·실제 이탈 시각과 인원, 출처        |
| 이동      | 근사 시간과 장소 연결 표시                             | 실제 길찾기·우회비율(45%/50%)·도착 시점 예측 |
| 리플레이  | 버튼으로 켠 예보/관측 인구 예시, 누락 포함             | 실제 관측·예보 이력·누락 표기·날짜 조회 API  |

예시 수요 구간의 경계와 이동 시간 계산은 화면 확인 목적이다. 실제 택시 승차 건수·기사 수입 증가·검증된 모델 성능으로 주장하지 않는다.
실제 API 예정 경로는 `/heatmap`, `/alerts/top`, `/places/{id}`, `/events`, `/routes/recommend`, `/replay/days/{date}`이며 기존 서버와의 경로·필드 차이는 백엔드 담당자와 확정한다.

## 저장 보존

기존 `netradar:v1:*` 운행·기록은 변환하거나 지우지 않는다. v2 모의 운행은 `netradar:v2:<계정>:demand-drive`, 알림 설정은 `netradar:v2:<계정>:preferences`에 별도 버전으로 저장한다.
v2 운행은 완료 상태와 기록을 같은 저장 문서에 반영하며 ID·revision으로 중복 입력을 막는다. 계정이 바뀌면 이전 계정 저장 상태를 사용하지 않는다.
정식 v2 API 연동 및 기존 운행 데이터 이전 정책은 별도로 결정한다. 로그인·프로필 저장 계약은 기존 동작을 재사용한다.

## 검증 명령

`front/`에서 `npm run typecheck`, `npm test`, `npm run build`, `npm run format:check`, `npm run test:e2e:v2`를 실행한다.
`npm run test:e2e`는 기존 v1 데모 회귀, `npm run test:e2e:live`는 격리된 v1 HTTP·인증 응답 회귀를 확인한다. 실제 인증·메일·운영 DB·예측 데이터 통합 검증을 대체하지 않는다.
구주제 WBS 4.1~4.5의 진행률은 v2 완료율로 전용하지 않는다.
